## Живые React-демо в кейсах

В будущем можно заменить часть скриншотов живыми демо компонентов, сделанных на работе. Саму страницу кейса при этом оставить на Pug + SCSS: так сохранятся текущая структура сайта, быстрая загрузка и SEO. React использовать только для интерактивных «островов».

### Что потребуется

- Установить `react` и `react-dom`.
- Добавить Babel-конфиг с `@babel/preset-react`: сейчас `babel-loader` подключён, но конфигурации для JSX нет.
- Расширить правило Webpack с `.js` до `.js` и `.jsx`.
- Если исходные компоненты написаны на TypeScript, добавить поддержку `.ts` / `.tsx`.
- Подгружать каждое демо через динамический `import()`, чтобы React не попадал в общий бандл всех страниц.
- Проверить зависимости рабочих компонентов: внутреннюю дизайн-систему, алиасы, CSS Modules, `next/image` и другие специфичные импорты придётся адаптировать.

### Изоляция стилей

Глобальные стили сайта применяются к `p`, `h2`, `ul`, `blockquote` и другим HTML-тегам. Они могут изменить внешний вид React-компонента; стили самого компонента, в свою очередь, могут повлиять на статью.

Предпочтительный вариант для сложных рабочих компонентов:

1. Собирать каждое демо как отдельное приложение в `built/demos/<name>/`.
2. Вставлять его в Pug-страницу через `iframe`.

Это изолирует стили и зависимости и позволит переносить рабочий код с меньшим количеством изменений.

Для небольших и хорошо изолированных компонентов допустим второй вариант: добавить контейнер в Pug и монтировать React прямо в страницу через динамический импорт.

### Перед реализацией

Сначала сделать proof of concept с одним простым компонентом и проверить:

- размер загружаемого JavaScript;
- корректность стилей внутри статьи;
- адаптивность;
- доступность;
- работу production-сборки;
- отсутствие React в бандле страниц без демо.
